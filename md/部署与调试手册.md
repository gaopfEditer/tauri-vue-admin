# Pharmaceutical Net Pro — 部署与调试手册

> 适用：本仓库桌面端（Vue 3 + Tauri + 本地 Axum API）  
> **现场临时默认数据库：SQLite**（无需安装 MySQL）；正式交付可再切回 MySQL。  
> 关联文档：
> - **`md/现场调试指导手册.md`** — 现场接传感器与联调（优先给现场工程师）
> - `md/设备联调与接入说明.md` — 设备网络与 Modbus
> - `md/软件授权-License说明.md` — 时间锁 / MAC 锁
> - `md/设备传感器-功能与操作流程.md` — 传感器业务
> - ApexRp 设备手册 PDF（`md/248083480-1 R2 ...`）

## 1. 系统架构（交付形态）

```text
┌─────────────────────────────────────────────┐
│  工控机 / 操作站                             │
│  ┌─────────────┐    ┌────────────────────┐  │
│  │ Tauri 窗口   │◄──►│ Rust API :8080     │  │
│  │ Vue 前端     │    │ · 业务 CRUD        │  │
│  └─────────────┘    │ · License 校验     │  │
│                     │ · Modbus 轮询主站   │  │
│                     │ · 统一 Debug 日志   │  │
│                     └─────────┬──────────┘  │
│                               │             │
│                     ┌─────────▼──────────┐  │
│                     │ SQLite field-test  │  │
│                     │ (或 MySQL 正式库)  │  │
│                     └────────────────────┘  │
└───────────────────────────────┬─────────────┘
                                │ Modbus TCP :502
                    ┌───────────▼───────────┐
                    │ ApexRp 粒子计数器等    │
                    └───────────────────────┘
```

要点：

- 前端**不要**单独用 `pnpm dev` 当现场环境（不会起 Rust API）。
- 设备**不会**主动连 `:8080`；由软件轮询设备。
- Windows 现场包：`pnpm build:tauri` → 安装包 / exe。
- Debug：顶栏 LAN 图标 / `Ctrl+Shift+D`，含 **system / db / modbus** 日志；文件 `logs/app.log`、`logs/modbus-poll.log`。

## 3. 数据库部署

### 3.0 现场临时：SQLite（当前默认）

根目录 `.env`：

```env
DB_DRIVER=sqlite
DB_SQLITE_PATH=database/sqlite/field-test.db
```

首次启动会自动：

1. 创建 `database/sqlite/field-test.db`
2. 执行 `database/sqlite/field-schema.sql`
3. 若无用户则灌入 `database/sqlite/field-seed.sql`（菜单含设备轮询联调 / 授权管理）

重置库：删掉 `field-test.db` 后重启即可。

### 3.1 MySQL（正式环境备用）

> 当前 Rust 后端为方便现场联调**仅编译 SQLite**；切回 MySQL 需改 `Cargo.toml` / `db.rs` 并恢复方言。保留下列脚本供正式库初始化。

```bash
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS soybean_admin DEFAULT CHARSET utf8mb4;"
```

### 3.2 MySQL 建议执行顺序

在项目根目录（按实际已落地的脚本执行；若某文件已跑过可跳过）：

```bash
# 基础库
mysql -u root -p soybean_admin < database/mysql/schema.sql
mysql -u root -p soybean_admin < database/mysql/init-data.sql

# 业务（pharma / ops / sys / facility / device / license）
mysql -u root -p soybean_admin < database/mysql/pharma-schema.sql
mysql -u root -p soybean_admin < database/mysql/pharma-seed.sql
mysql -u root -p soybean_admin < database/mysql/pharma-ops-schema.sql
mysql -u root -p soybean_admin < database/mysql/pharma-ops-seed.sql
mysql -u root -p soybean_admin < database/mysql/pharma-sys-schema.sql
mysql -u root -p soybean_admin < database/mysql/pharma-sys-seed.sql
mysql -u root -p soybean_admin < database/mysql/pharma-facility-schema.sql
mysql -u root -p soybean_admin < database/mysql/pharma-facility-seed.sql
mysql -u root -p soybean_admin < database/mysql/pharma-device-config-schema.sql
mysql -u root -p soybean_admin < database/mysql/pharma-device-config-seed.sql
mysql -u root -p soybean_admin < database/mysql/pharma-license-schema.sql
```

也可用仓库内 `database/mysql/install.sql` / `setup-local.sh`（若存在且内容覆盖上述范围）。

菜单变更后需**重新登录**才能看到新菜单。

## 4. 配置文件（`.env`）

项目根目录 `.env`（打包前按现场改）：

```bash
VITE_DESKTOP_API=Y              # 走本地 8080，必开
VITE_AUTH_ROUTE_MODE=dynamic

# 现场临时默认 SQLite
DB_DRIVER=sqlite
DB_SQLITE_PATH=database/sqlite/field-test.db

# MySQL 备用项（当前后端未启用 mysql feature）
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=soybean_admin
DB_USER=root
DB_PASSWORD=********

# 授权：开发可 Y；现场交付必须 N，并更换密钥
LICENSE_BYPASS=N
LICENSE_SECRET=请更换为厂商密钥
LICENSE_MASTER_KEY=请更换为签发密钥

# Modbus 轮询
MODBUS_POLL_ENABLED=Y
MODBUS_POLL_INTERVAL_SEC=5
MODBUS_POLL_LOG_DIR=logs
```

| 变量 | 说明 |
|------|------|
| `DB_DRIVER` | 当前仅 `sqlite` |
| `DB_SQLITE_PATH` | SQLite 文件路径 |
| `LICENSE_BYPASS=Y` | 跳过授权（仅开发） |
| `MODBUS_POLL_ENABLED` | `Y` 启动后台轮询 |
| `MODBUS_POLL_INTERVAL_SEC` | 轮询周期（秒） |
| `MODBUS_POLL_LOG_DIR` | 日志目录，默认 `logs`（含 `app.log` / `modbus-poll.log`） |

## 5. 开发启动

```bash
pnpm i
pnpm dev:tauri          # 正确：前端 + Tauri + Rust API
# pnpm dev              # 错误（现场/联调不要用）：不起 8080
```

自检：

1. Debug / 控制台出现 SQLite 连接成功、`desktop api` 在 `http://127.0.0.1:8080`
2. 窗口能打开登录页
3. 顶栏有 **局域网 Debug 图标**

端口占用：

```bash
lsof -ti:5183 | xargs kill -9   # Vite
# 8080 被占用时结束旧 Tauri/API 进程后重启
```

## 6. 生产打包与安装（Windows exe）

> **Windows 安装包 / exe 请在 Windows 上构建。**  
> 只有 Mac 时：用仓库 GitHub Actions（推荐），或 Windows 虚拟机 / 云主机。

### 6.0 GitHub Actions 出包（推荐，仅有 Mac 也可用）

仓库已配置：`.github/workflows/build-windows.yml`

**怎么跑：**

1. 代码推到 [gaopfEditer/tauri-vue-admin](https://github.com/gaopfEditer/tauri-vue-admin)
2. GitHub → **Actions** → **Build Windows** → **Run workflow**
3. 等待绿色勾 → 打开该次 run → **Artifacts** 下载 `pharmanet-windows-***`
4. 或打标签发布：`git tag v0.1.0 && git push origin v0.1.0` → 自动构建并挂到 Release

产物一般包含：

- `soybean-admin.exe`（免安装）
- `*.msi` / NSIS `*.exe`（安装包）

### 6.1 本机构建环境（Windows 打包机）

| 依赖 | 说明 |
|------|------|
| Node.js 18+、pnpm | 前端构建 |
| Rust（stable） | `rustup` 安装 |
| Visual Studio Build Tools | C++ 桌面开发工作负载（MSVC） |
| WebView2 | 目标机 Win10/11 一般已有；缺失时安装官方 Runtime |

### 6.2 本机一键打包

在仓库根目录：

```bash
pnpm i
pnpm build:tauri
```

等价于 `pnpm tauri build`：先跑前端 `build`，再编 Rust release 并打安装包。

### 6.3 产物在哪

| 类型 | 典型路径 |
|------|----------|
| 免安装可执行文件 | `src-tauri/target/release/soybean-admin.exe` |
| 安装包（推荐交付） | `src-tauri/target/release/bundle/msi/` 或 `.../nsis/` |
| macOS | `.../bundle/dmg/`（需在 Mac 上编） |
| Linux | `.../bundle/deb` / AppImage |

现场交付优先给 **msi/nsis 安装包**；调试可用同目录下的 `soybean-admin.exe`。

### 6.4 现场安装清单（临时 SQLite）

1. 安装本软件（exe/msi）  
2. 确认能登录（默认 `Admin` / `admin123`）  
3. 配置授权（正式：`LICENSE_BYPASS=N` 并激活）  
4. 按 `md/现场调试指导手册.md` 接传感器并确认 `poll_ok`  
5. 修改默认管理员密码  

详细接入步骤见：**`md/现场调试指导手册.md`**。

## 7. 软件授权（交付必做）

1. 厂商用 `LICENSE_MASTER_KEY` 在「系统运维 → 授权管理」**签发**（填有效期，勾选设备锁）  
2. 现场打开 `/license` 或授权页 **激活** → 绑定本机 MAC  
3. 到期 / 换机 / 大幅回拨系统时间 → 锁定，需新授权码  

详见：`md/软件授权-License说明.md`。

## 8. 设备接入与轮询调试

### 8.1 网络

1. ApexRp：Setup Tool 配静态 IP，**拔掉 SmartPort**  
2. 与工控机同网段，`ping` 通；Modbus TCP 端口多为 **502**  
3. 软件「粒子」→ 配置：
   - 协议：`ModbusTCP`
   - **PLC IP = 设备真实 IP**（禁止 `PLC1` 占位）
   - 从机地址 = Unit ID（通常 `1`）

### 8.2 哪里开启 / 查看轮询

| 入口 | 路径 / 操作 | 作用 |
|------|-------------|------|
| 自动 | `MODBUS_POLL_ENABLED=Y` 且进程已启动 | 后台按周期轮询 |
| Debug 面板 | 顶栏局域网图标 或 `Ctrl+Shift+D` | 实时日志、启停、单次测通 |
| 联调页 | **系统运维 → 设备轮询联调** `/system/device-poll` | 完整日志与测通 |
| 文件 | `logs/modbus-poll.log` | 断电后仍可追溯 |

默认 **出错自动弹出** Debug 面板（可在面板内关掉）。

### 8.3 成功标志

Debug 日志出现：

- `connect` → `poll_ok`（带 status / flow / ch1 / ch2）
- 粒子卡片 / 实时信号数值更新
- 失败则为 `ERROR` + `com_alarm`，状态 Offline

### 8.4 单次测通

在 Debug 面板或联调页填 **传感器 ID**（库表 `ph_sensor.id`）→「单次测通」。

## 10. 故障排查

| 现象 | 排查 |
|------|------|
| 白屏 / 接口全失败 | 是否用了 `dev:tauri`；8080 是否在听；`VITE_DESKTOP_API=Y` |
| 登录失败「授权无效」 | `LICENSE_BYPASS`；或去 `/license` 激活 |
| 菜单缺少「设备轮询联调」 | 执行 license/device 相关 seed；**重新登录** |
| 日志一直 `skip` / 占位 IP | `plcIp` 改成真实 IP |
| 日志 `连接超时` | ping、防火墙、设备 IP/网段、502 端口 |
| `Modbus 异常码` | Unit ID、寄存器映射与固件是否匹配 |
| 5183 端口占用 | `lsof -ti:5183 \| xargs kill -9` |
| MySQL 连不上 | `.env` 密码；服务是否启动；远程权限 |
| ON/OFF 界面变了设备没动 | 看 Debug 是否有 `command` 写 40002；网络是否通 |

## 11. 推荐联调当天流程（一页纸）

```text
1. 启动桌面端（安装好的 exe，或开发机 pnpm dev:tauri）
2. 登录；Ctrl+Shift+D 打开 Debug（确认 db/system 日志）
3. 激活 License（现场）或确认 BYPASS（实验室）
4. 粒子点配置真实 IP + ModbusTCP + Unit ID
5. 看日志 poll_ok；不行先 ping / Modbus Poll 工具
6. 卡片数值与 ON/OFF 命令验证
7. 改默认密码；记录授权到期日
```

完整逐步操作见：`md/现场调试指导手册.md`。

## 12. 已知限制

- 当前轮询仅 **Modbus TCP**；RTU / OPC UA 未做  
- 无网段自动发现，需手工配 IP  
- 寄存器地址按 ApexRp 手册默认映射；特殊固件可能要改 `src-tauri/src/modbus_poll.rs`  
- `LAST_VALUE` 在 MySQL 8 为保留字，SQL 须写 `` `last_value` ``（代码已处理）
